================================================================
一、这一版改了什么
================================================================

【速度】
v1.0 每转换一张图都要重新启动一次 texconv.exe，每次启动约有 0.4~0.5 秒
的固定开销（进程创建 + DirectXTex 初始化 + 杀毒扫描），小图时这部分比
真正的压缩还慢。v1.1 改成一次把多个文件交给同一个 texconv 进程处理，
并顺手去掉了「每个 PNG 都复制一份到临时目录」的无效 IO。

实测（同一台机器，Windows 11）：
    60 张 256px 贴图：  18.5 秒 -> 2.9 秒   约 6.5 倍
    24 张 1024px 贴图： 11.5 秒 -> 5.7 秒   约 2.0 倍
（图越大，压缩本身占比越高，所以倍数会下降，但启动开销始终被摊薄。）

【修掉的 Bug】
1. 带 Alpha 的 PNG 转 BC1 会出现黑块。
   texconv 默认按 0.5 阈值把 Alpha 压成 1 bit，被判为透明的像素颜色会被
   抹成黑色；而 FFXIV 的 BC1(0x3420) 是纯不透明格式，游戏里就会看到一块
   块黑斑。现在 BC1 一律按不透明压缩，颜色完整保留（半透明像素的 RGB 误差
   从 123 降到 1），仍会提示「BC1 不支持平滑透明度」。
2. 非正方形贴图选尺寸会被拉变形。
   v1.0 把 -w N -h N 同时传给 texconv，1024x512 的图集会被强行拉成
   1024x1024。现在按长边等比缩放（512x128 + 长边 128 -> 128x32），
   并把宽高对齐到 4 的倍数（BC 块要求）。
3. 「自动推荐」区域的文字和勾选框挤在同一个网格单元格里，互相覆盖。
   已重排为独立控件。
4. 不同子目录里的同名文件会写到同一个输出文件、互相覆盖。
   现在输出名自动去重（body_d.tex / body_d_2.tex）。
5. 设置只在点「开始」时保存，关闭窗口就丢。现在关闭时也会保存，
   并自动迁移 v1.0 的设置。
6. 目录扫描把 *.png 和 *.PNG 分别递归两遍，几百个文件时明显卡顿。
   现在一次遍历完成，PNG 和 TEX 同时收集。

【用起来更顺】
* 新增「取消」按钮：立即终止正在运行的 texconv，不会再卡住。
* 进度条显示百分比、已用时间和剩余时间。
* 日志按类型上色（成功绿 / 失败红 / 警告橙），并显示输出体积和压缩比：
      ✓ body_d.png → body_d.tex [BC1_UNORM, 42.8 KB]
      ✓ xxx.tex (BC7_UNORM, 256x256, 9 mip) → xxx_converted.tex [BC1_UNORM, 85.4 KB → 42.8 KB (-49%)]
* TEX 已经是目标格式时默认跳过重压缩（可关闭），既省时间又避免二次损失。
* 支持 PNG + TEX 一起拖入，按各自规则处理。
* 拖入文件夹时自动把「PNG 输入」填上，配合输出目录可以保留子目录结构。
* 支持 125% / 150% 系统缩放（DPI 感知），窗口按内容自适应、不会超出屏幕。
* 记住窗口大小和位置。

【稳定性】
* TEX 一律「写临时文件 + 原子替换」，取消或崩溃不会留下半个文件。
* 一批文件里只要有一个出错，会自动退化为逐个重跑，精确指出是哪个文件、
  错误原文是什么（中文错误信息不会变乱码）。
* DDS/TEX 全程流式读写，4096 贴图不再整份读进内存。
* 批量转换中途出错不会中断整批，最后汇总「成功 / 失败 / 跳过」。
* 无控制台的 EXE 出错时会把堆栈写进日志：
      %APPDATA%\Miili\FFXIV贴图批量转换器\error.log

================================================================
二、怎么用
================================================================

1. PNG -> TEX
   - 把 PNG 文件/文件夹拖进窗口，或点「PNG 输入 → 选择…」。
   - 「输出格式」选 BC1 / BC3 / BC5 / BC7 / BGRA8。
   - 勾选「按文件名逐个推荐」时，每张 PNG 会按自己的名字推荐格式
     （diffuse→BC1、normal→BC7、_rg→BC5 …），日志里会写清楚。
   - 「TEX 输出」留空 = 生成在源文件旁边；选了目录则保留原有子目录结构。
   - 点「开始 PNG→TEX」。

2. TEX -> TEX（换压缩格式）
   - 点「批量 TEX 格式转换…」选文件，或直接把 .tex / 文件夹拖进窗口。
   - 「输出格式」是目标格式。
   - 默认输出 *_converted.tex；也可勾选「TEX→TEX 直接覆盖源文件」（有确认提示）。
   - 源文件已是目标格式时默认跳过，避免重复压缩掉画质。

3. 尺寸
   「图片尺寸」按长边等比缩放，不会把非正方形贴图拉变形。
   长边已经等于目标值时不重复缩放。

4. 取消
   转换过程中点「取消」，正在跑的 texconv 会被立刻结束。

================================================================
三、从源码构建 EXE
================================================================

1. 安装 Python 3.10+（勾选 Add Python to PATH）。
2. 双击 BUILD_EXE.bat。
   脚本会自动安装 PyInstaller、准备 texconv.exe，然后打包。
3. 成品：dist\FF14.Tex.Converter.exe

说明：
* tools\texconv.exe 已经随包提供（Microsoft DirectXTex 2026.5.8）。
  若被删掉，首次转换时会自动从官方 GitHub Release 下载
  （NuGet 作为备用源）。
* BUILD_EXE.bat / CLEAN_BUILD.bat 全部使用 ASCII，避免 CMD 中文乱码。
* 只想要 Python 源码版本：python main.py，效果一样。

================================================================
四、自检（排查「转换失败」时很有用）
================================================================

    "FF14.Tex.Converter.exe" --selftest

会在同目录生成 selftest_report.json，内容包括：
  * texconv 是否找到、版本号
  * PNG -> BC7/BC5/BC3/BC1/BGRA8 五种格式是否都能生成
  * 每个 TEX 的格式 ID、尺寸、mip 层数、文件长度是否自洽
  * TEX -> TEX 换格式是否正常
  * 等比缩放计算是否正确
全部通过时 ok 为 true。

================================================================
六、已知限制
================================================================

* 只支持 FFXIV 的 2D TEX（BGRA8 / BC1 / BC3 / BC5 / BC7）。
  立方体贴图、数组贴图、3D 贴图，以及 BC4、BC6H 等格式会明确报错，不会瞎猜。
* BC1 是纯不透明格式，无法保存平滑 Alpha；需要透明度请用 BC3 / BC7。
  （完全透明的像素在 BC1 里会变成黑色，程序会提示。）
* BGRA8 不做压缩，体积最大，只在需要无损时使用。
* 只支持 Windows（texconv 是 Windows 程序）。

v1.3 修复（2026-10-29）
- 【严重】修复「点『开始』后什么都没发生、日志只有一行 ✗ 构建任务失败：'input'」。
  原因：v1.1 起「PNG 输入」不再写进设置文件，但 build_jobs() 仍然读取
  settings["input"]，于是每次转换都在动手之前抛出 KeyError('input')，
  任何 PNG→TEX / TEX→TEX 都不可能成功。现在输入路径只作为本次运行参数传递
  （不落盘），读取也改成安全取值 settings.get("input")。
- 新增无界面转换模式，便于排查和脚本批量处理：

      "FF14.Tex.Converter.exe" --convert <文件或文件夹> [输出目录] [--format BC1_UNORM]

  走的和界面「开始」按钮完全相同的流程，结果写进 输出目录\convert_report.json，
  全部成功返回 0，有失败返回 1。
- dist\FFXIV贴图批量转换器ver1.3.exe 已用修复后的源码重新打包；
  修复前的旧文件备份在 dist\_backup\ 里。
